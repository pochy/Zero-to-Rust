# Sol 000: 死ぬ理由の棚卸し

対応教材: [Level 0: Rust の設計思想とメンタルモデル](../levels/level_00_philosophy/README.md)

## 状況

砂嵐が去った。

HAB の外壁はまだ立っている。酸素生成機も、今のところ文句を言わずに動いている。問題は「今のところ」という部分だ。

マークは医療キットの横で、左腹部の痛みを無視しながら端末を開いた。通信はない。救助予定もない。あるのは、在庫リストと、妙に厳格な Rust コンパイラだけだった。

「よし。死ぬ理由を数えよう」

彼は声に出した。誰も聞いていない。だからこそ、声に出す必要があった。

```text
食料が足りない。
水が足りない。
通信がない。
移動距離が長すぎる。
ログが壊れたら復旧できない。
ローバーを並行改造したら手順が衝突する。
所有者が分からないデータは、いつか誰かを殺す。
```

最後の一行を書いたところで、マークは笑った。

「火星で死ぬ理由に、所有権の曖昧さが入る日が来るとはな」

## ログ

**LOG 000.1**

マーク:

「まず哲学だ。火星で哲学。すばらしい。酸素が有限なのに、俺は『このデータは誰が所有するのか』を考えている。だが、たぶんこれが正しい」

「水タンクを誰が管理しているか曖昧なら、誰かが勝手に使う。食料庫の鍵を誰が持つか曖昧なら、在庫は数えられない。メモリも同じだ。所有者が曖昧なものは、いつか破裂する」

端末に、Level 0 の問いを写す。

```text
誰が所有するか
誰が借りるか
いつ解放されるか
失敗をどこで扱うか
共有してよい状態か
```

マーク:

「これはコードの話じゃない。生存管理表だ」

数時間後、地球側の管制がまだ彼の生存に気づいていないころ、マークは自分だけの設計会議を始めた。

マーク:

「議題一。`clone()` は悪か」

マーク:

「反対意見。悪ではない。ジャガイモを増やすのは悪ではない。ただし、理由もなく増やすと食料計画が壊れる」

マーク:

「議題二。`unwrap()` は悪か」

マーク:

「火星で『これは絶対失敗しない』と言う人間は、だいたい次の場面で爆発する。よって I/O では `Result` を使う」

## Rust 任務

Level 0 では、大量のコードを書かない。代わりに、以後の全任務で使う判断軸を作る。

読むもの:

- [ownership_canvas.md](../levels/level_00_philosophy/examples/ownership_canvas.md)
- [Level 0 exercises](../levels/level_00_philosophy/exercises.md)

書くこと:

```text
ファイルを読み込んで表示する CLI では、
どの値がどこで生まれるか。
どの関数が所有するか。
どの関数は読むだけか。
どの処理は失敗するか。
どこでエラーを表示するか。
```

## 管制との仮想会話

管制:

「マーク、なぜ最初に文法を覚えない？」

マーク:

「文法はあとでいい。いま必要なのは、HAB の水を誰が所有するかだ。水を借りて飲むやつと、水タンクを持ち去るやつは違う」

管制:

「それは Rust の話か？」

マーク:

「火星では全部 Rust の話になる」

## 進級チェック

次の問いに答えられたら、Sol 006 へ進む。

```text
所有権を、メモリ管理ではなく責任範囲として説明できるか。
借用を、所有者を変えずに一時利用する設計として説明できるか。
Result を、失敗を隠さず上位へ渡す契約として説明できるか。
clone と unwrap を、便利コマンドではなく設計判断として扱えるか。
```

マークのメモ:

「今日の結論。Rust は俺を困らせているのではない。俺が未来の俺を困らせないよう、今ここで止めてくれている」
