# Sol 097: 「動いた」を信用しない

対応教材: [Level 6: テスト、評価、失敗分析](../levels/level_06_evaluation/README.md)

## 状況

九十七日目。

地球との通信が成立した。NASA は救援計画を動かし始めた。マークは喜んだ。五分だけ。

その後、彼は自分のコマンドパーサーを見て黙った。

「これ、本当に不正入力で落ちないか？」

火星では「たぶん動く」は危険だ。地球でも危険だが、火星では訂正の余地が少ない。

## ログ

**LOG 097.1**

マーク:

「テストを書く。いや、違う。仕様を固定する。テストは、未来の俺に向けたメッセージだ。『ここを壊したら過去の俺が火星から怒る』というメッセージだ」

彼はテストを実行した。

```bash
rustc --edition=2021 --test levels/level_06_evaluation/examples/parser_tests.rs -o /tmp/zero_to_rust_parser_tests
/tmp/zero_to_rust_parser_tests
```

期待する出力には、複数の `ok` と最後の `test result: ok` が含まれる。

マーク:

「正常系だけでは足りない。`GET` だけ送った場合、空行、余計な引数、知らないコマンド。火星は親切な入力だけを送ってこない」

## 会話

管制:

「コンパイルが通れば安全では？」

マーク:

「メモリ安全性と仕様の正しさは別だ。コンパイルが通る酸素生成機でも、酸素ではなく水素を部屋に流していたら俺は終わる」

管制:

「失敗はどう分類する？」

マーク:

「最低でもこうだ」

```text
入力エラー:
不正なコマンド。ERROR を返す。

状態エラー:
存在しないキー。NOT_FOUND を返す。

I/O エラー:
接続断やファイル失敗。Result で伝播する。

並行処理エラー:
ロック競合。設計を見直す。

運用エラー:
ログ不足。復旧手順を足す。
```

管制:

「全部 `String` のエラーでよいか？」

マーク:

「初期段階ならありだ。だが分類が増えたら `enum ParseError` が欲しくなる。大事なのは、いつ変えるかを判断することだ」

## Rust 任務

1. `parser_tests.rs` を実行する。
2. `EXISTS key` の正常系と異常系テストを追加する。
3. わざと期待値を間違えて、失敗メッセージを読む。
4. `String` エラーと `enum ParseError` の違いを説明する。

演習:

- [Level 6 exercises](../levels/level_06_evaluation/exercises.md)

## マークの独り言

「テスト失敗の出力は嫌なものだ。赤いし、長いし、俺の自尊心に優しくない」

「だが、テスト失敗は、火星の警告灯の中ではかなり親切な部類だ。少なくとも、どこで何が違うか言ってくれる」

```text
期待する入力を決める。
期待する出力を書く。
境界値を追加する。
失敗時の分類を書く。
テストを実行する。
失敗したら原因を分類する。
```

マーク:

「これができれば、『動いた気がする』から抜け出せる。火星で気分に頼るな。測れ」

## 進級チェック

次の問いに答えられたら、Sol 141 へ進む。

```text
正常系と異常系の両方をテストできるか。
コンパイル成功と仕様正しさの違いを説明できるか。
失敗を入力、状態、I/O、並行、運用に分類できるか。
エラー型をいつ `String` から `enum` に変えるか判断できるか。
```

マークのメモ:

「今日はコードではなく、未来の事故をいくつか殺した」
