# Level 0: Rust の設計思想とメンタルモデル

## この Level でできるようになること

Rust を「速い言語」や「難しい言語」としてではなく、責任範囲を型で表す言語として捉えられるようになります。

この Level ではコードを大量に書きません。代わりに、後のすべての Level で使う判断軸を作ります。

```text
誰が所有するか
誰が借りるか
いつ解放されるか
失敗をどこで扱うか
共有してよい状態か
```

## まずは日常語で考える

この Level では、Rust の詳しい文法を覚える必要はありません。最初に知ってほしいのは、Rust がコードに次の責任を書かせる言語だということです。

| 問い | 日常語での意味 | 後で Rust の何につながるか |
| --- | --- | --- |
| 誰が持つか | そのデータを最後まで管理するのは誰か | 所有権 |
| 誰が見るだけか | データを受け取らず、一時的に読むだけなのは誰か | 借用 |
| いつ不要になるか | そのデータをいつ片付けてよいか | ライフタイム |
| 失敗したらどうするか | ファイルがない、入力が変、通信が切れた時にどう扱うか | エラー処理 |
| 同時に触ってよいか | 複数の処理が同じデータを読む・変える時にどう守るか | 共有状態 |

この表の右側の言葉は、今すぐ暗記しなくて構いません。後の Level でコードを動かしながら、少しずつ意味を確認します。

## この Level で使う言葉

- 所有権: 値を最後まで管理する責任。
- 借用: 所有権を渡さず、一時的に値を使うこと。
- ライフタイム: 借りている値を、いつまで安全に使えるかという範囲。
- 失敗: ファイルがない、入力が間違っている、通信が切れるなど、自然に起きること。
- 共有状態: 複数の処理から同じデータに触る設計。
- 境界: 関数、モジュール、スレッド、プロセスなど、責任が切り替わる場所。

詳しい用語は [glossary.md](../../docs/reference/glossary.md) で確認できます。ただし、この Level では上の短い説明で十分です。

## なぜこれを学ぶのか

初心者は Rust を「コンパイラが厳しい言語」と感じがちです。プロは少し違う見方をします。

```text
初心者の見方:
コンパイルエラーを消すために、とにかくコードを足す。

プロの見方:
コンパイルエラーは、所有、借用、失敗、共有の設計が曖昧な場所を指している。
```

Rust は、後から事故になる曖昧さを早い段階で表面化させます。そのため、このチュートリアルでは最初に文法一覧ではなく、設計思想を扱います。

## 手順 1: 所有権キャンバスを書く

[examples/ownership_canvas.md](examples/ownership_canvas.md) を開き、そこにある問いを 1 つずつ読んでください。

最初は正解を書こうとしなくて構いません。大事なのは、Rust のコードを書く前に次の問いがあると知ることです。

```text
このデータはどこで生まれるか
どの関数が所有するか
どの関数は読むだけか
どの処理は失敗するか
どこから並行アクセスされるか
```

## 手順 2: 悪いメンタルモデルを見つける

次のように考えている箇所があれば、後で必ずつまずきます。

```text
コンパイルが通らないから、意味を考えずにコードを増やす
エラーが面倒だから、失敗しないことにする
共有したいから、何でも同じ場所に置く
ライフタイムは難しいから避ける
```

良い出発点は、次のように言い換えることです。

```text
値を複製するなら、なぜ複製が必要か説明する
失敗する処理なら、誰が失敗を扱うか決める
共有する状態なら、どの範囲だけ共有するか決める
ライフタイムは参照の依存関係を表す設計判断
```

後の Level では、この考え方が `clone()`、`unwrap()`、`Result`、`Arc<Mutex<T>>` という具体的な名前で出てきます。ここでは名前を覚えるより、「責任を説明してから使う」という姿勢だけ持ってください。

## 手順 3: 後の Level へ接続する

Level 1 では、`String` を渡すか `&str` を渡すかを観察します。

Level 2 では、失敗するファイル読み込みを扱います。そこで `Result` という「成功か失敗かを表す型」を学びます。

Level 3 では、`HashMap<String, String>` を構造体に所有させます。

Level 5 以降では、TCP 接続、スレッド、WAL、復旧の責任境界を設計します。これらは後で説明するので、今は名前だけで十分です。

どの Level でも、中心の問いは変わりません。

```text
この責任はどこに置くべきか
```

## よくあるつまずき

```text
Q. 最初からライフタイムを深く学ぶべきですか？
A. まずは所有型を使い、関数引数で借用を使うところから始めます。構造体に参照を持たせる設計は後で扱います。
```

```text
Q. clone や unwrap という言葉が他の資料に出てきます。今覚えるべきですか？
A. まだ深く覚えなくて大丈夫です。clone は Level 1-3、unwrap と Result は Level 2 で、実際のコードと一緒に扱います。
```

## 次の Level に進む条件

次を自分の言葉で説明できたら、Level 1 に進んでください。

```text
所有権は何の責任を表すか
借用はなぜ便利か
失敗を設計に含めるとはどういうことか
共有状態を小さくするとはどういうことか
```

## Rust らしさをさらに深掘りする

Rust を学ぶ意味は、構文を覚えることではなく、曖昧な責任をコードの形に変えることです。所有権はメモリだけでなく、API、スレッド、エラー、復旧にも広がります。

この Level の後で、次の補講を読んでください。

- [所有権、借用、ライフタイム完全補講](../../appendices/01_ownership_lifetimes.md)
- [Professional Rust Map](../../appendices/08_professional_rust_map.md)

特に意識する問い:

```text
型に書かれていない責任はどこに残っているか
失敗したとき、誰がどう扱うか
後で並行化したとき、何が共有状態になるか
```
