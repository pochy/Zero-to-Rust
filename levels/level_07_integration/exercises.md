# Level 7 Exercises

## 1. 小さく変更する

`thread_pool.rs` のワーカー数を 2 から 4 に変え、出力順がどう変わるか観察してください。

## 2. 出力を比較する

ジョブ内に `std::thread::sleep` を追加し、短いジョブと長いジョブを混ぜて実行してください。

実行順、終了順、`all jobs submitted` の表示位置を比較します。

## 3. 設計判断を書く

共有 Store を次のどちらで包むか判断してください。

```rust
Arc<Mutex<Store>>
Arc<RwLock<Store>>
```

`Arc` は複数スレッドから同じ状態を指すための道具です。`Mutex` は同時に 1 つだけが中身を変更できるようにする道具です。`RwLock` は読み取りが多い場合に候補になる発展的なロックです。

読み取りが多い場合、書き込みが多い場合、実装の単純さを分けて考えます。

## 提出物

```text
1. ワーカー数を変えた実行結果
2. sleep を入れたときの順序の観察
3. Mutex と RwLock の選択判断
```


## 追加演習: channel 設計と比較する

共有 Store を `Arc<Mutex<Store>>` で守る設計と、Store 専用スレッドへ channel で `Command` を送る設計を比較してください。

この追加演習は発展です。必須課題では、まず `Arc` と `Mutex` の役割を分けて説明できれば十分です。

```text
所有権の流れ
ロックの有無
終了処理
テストしやすさ
遅いクライアントの影響
```
