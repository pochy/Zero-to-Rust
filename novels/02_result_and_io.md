# 02: 洞窟の記録と失敗を返す力

対応教材: [Level 2: 基礎実装編](../levels/level_02_basics/README.md)

## 物語パート

暴風竜の封印された洞窟には、古い石板がいくつも残されていた。

魔物の通行記録、勇者の痕跡、封印術式の断片。どれも、これから外へ出る俺にとって貴重な情報だ。

問題は、俺がそれを読めるかどうかだった。

「大賢者、石板の記録を読み込めるか？」

『告。ファイル I/O 相当の処理です。失敗可能性があります』

「また失敗か」

『解。存在しない記録、権限のない記録、壊れた記録、読めない文字コード。外部世界に触る処理は失敗します』

「異世界でもファイルは壊れるんだな」

『肯定。むしろ壊れていない前提が危険です』

俺は石板の表面をぷるんと包み込み、内容を読み取ろうとした。

```rust
use std::fs;
use std::io;

fn read_record(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}
```

読み取りは成功した。

だが、別の石板では失敗した。端が砕け、文字が半分消えていたのだ。

「これ、どうする？ 気合いで読む？」

『却下。失敗は気合いで消えません。`Result` として返します』

## 会話・独白パート

「`Result<String, io::Error>` って、成功したら文字列、失敗したらエラーってことか」

『解。正確です』

「じゃあ `unwrap()` でいいんじゃない？ 成功したら取り出せるんだろ」

『警告。`unwrap()` は失敗時に処理を停止させます』

「洞窟で止まるくらいなら、まあ」

『否定。将来それは国の中核処理になります。記録が一つ読めないだけで国家全体を停止させる設計は不適切です』

暴風竜が封印の奥で笑った。

「クワッハッハ！ 石板一枚で国が滅ぶとは、なかなか繊細な国家だな」

「笑い事じゃないな。ちゃんと返すか」

大賢者は、次の形を示した。

```rust
use std::env;
use std::fs;
use std::io;

fn main() -> Result<(), io::Error> {
    let path = env::args()
        .nth(1)
        .expect("usage: cargo run -- <path>");

    let content = fs::read_to_string(path)?;
    print!("{}", content);

    Ok(())
}
```

「`?` がある」

『解。`?` は、成功なら中身を取り出し、失敗ならそのエラーを呼び出し元へ返します』

「便利だな」

『補足。ただし、便利だから使うのではありません。失敗をこの場で処理せず、上位へ返す設計判断です』

俺は壊れた石板を見た。

読めないものは、読めない。

大事なのは、読めなかったという事実を隠さないことだった。

## 大賢者による解説

『告。Level 2 の目的は、失敗する処理を `Result` で扱うことです』

`std::fs::read_to_string` は、ファイルを読み込んで `String` を返す関数です。ただしファイルが存在しない、権限がない、読み込みに失敗するなどの理由で失敗する可能性があります。

そのため、戻り値は `Result<String, std::io::Error>` です。

『解。`Result<T, E>` は、成功時の値 `T` と失敗時のエラー `E` を型として表します』

悪い設計:

```rust
let content = std::fs::read_to_string(path).unwrap();
```

良い設計:

```rust
let content = std::fs::read_to_string(path)?;
```

`unwrap()` は、「ここでは絶対に失敗しない」と開発者が保証できる場合に限って使います。I/O では、基本的に失敗を前提にします。

## 初出用語・関数の説明

- `use`: モジュールや型を現在のスコープに持ち込むキーワード。
- `std::fs`: 標準ライブラリのファイルシステム操作モジュール。
- `std::io`: 入出力と I/O エラーを扱う標準ライブラリのモジュール。
- `Result<T, E>`: 成功なら `Ok(T)`、失敗なら `Err(E)` を表す型。
- `io::Error`: ファイルやネットワークなどの I/O 失敗を表すエラー型。
- `std::env::args`: コマンドライン引数を取得する関数。
- `nth(1)`: イテレータから 2 番目の要素を取り出すメソッド。
- `expect`: `Option` や `Result` から値を取り出し、失敗時に指定メッセージで停止するメソッド。
- `?`: 失敗時にエラーを呼び出し元へ返す演算子。
- `Ok(())`: 成功したが返す値が特にないことを表す。
