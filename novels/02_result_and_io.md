## 大賢者による解説

『告。Level 2 の目的は、失敗する処理を `Result` で扱うことです』

`std::fs::read_to_string` は、ファイルを読み込んで `String` を返す関数です。ただしファイルが存在しない、権限がない、読み込みに失敗するなどの理由で失敗する可能性があります。

そのため、戻り値は `Result<String, std::io::Error>` です。

『解。`Result<T, E>` は、成功時の値 `T` と失敗時のエラー `E` を型として表します』

悪い設計:

```rust
let content = std::fs::read_to_string(path).unwrap();
```

良い設計:

```rust
let content = std::fs::read_to_string(path)?;
```

`unwrap()` は、「ここでは絶対に失敗しない」と開発者が保証できる場合に限って使います。I/O では、基本的に失敗を前提にします。

### 補講: 失敗を普通の道として扱う

告。`Result` は、失敗を隠さないための型です。
解。ファイルを読む処理は、成功することも失敗することもあります。
存在しないファイルを読むかもしれません。
権限がなくて開けないかもしれません。
途中でディスクの状態が変わるかもしれません。
Rust は、そうした可能性を例外として遠くへ飛ばすのではなく、型として手元に置きます。
それが `Result<T, E>` です。
`T` は成功した時の値です。
`E` は失敗した時の理由です。

解。`Ok(value)` は成功です。
たとえばファイルの内容を読めたなら、`Ok(text)` のように返せます。
`Err(error)` は失敗です。
失敗した時には、なぜ失敗したのかを表す値を入れます。
`std::io::Error` は、ファイルや入出力で起きた失敗を表す代表的な型です。
ここで大切なのは、成功と失敗の両方が値として扱われることです。
値なら、関数から返せます。
値なら、テストできます。
値なら、物語の中で判断できます。

告。`?` は、怠けるための記号ではありません。
解。`?` は、失敗した時の流れを読みやすくするための記号です。
成功したら中身を取り出して次へ進みます。
失敗したら、その失敗を呼び出し元へ返します。
つまり `?` を使う関数は、失敗を返せる型でなければなりません。
多くの場合、戻り値は `Result<何か, エラー型>` になります。
`?` は魔法の回復ではなく、丁寧な早期帰還です。

解。`std::fs` は、ファイルシステムを扱う標準ライブラリの入口です。
`fs::read_to_string(path)` は、ファイル全体を文字列として読みます。
小さな設定ファイルや教材用データなら、とても便利です。
ただし巨大なファイルでは、一度に全部読むとメモリを多く使います。
その場合は `BufReader` などで少しずつ読む設計を考えます。
今の章では、まず「ファイルを読むと失敗があり得る」と知ることが目的です。

解。`std::io` は、読み書きの共通ルールを集めた場所です。
ファイル、標準入力、ネットワークなど、いろいろな入出力があります。
それらに共通する「読む」「書く」という振る舞いを扱います。
後の章で `BufRead` や `Write` が出てきます。
これらは、具体的な相手が何であっても、同じ考えで処理するための道具です。
洞窟の石板も、森の通信路も、Rust から見れば入力と出力の流れです。

提案。エラー処理は、初心者ほど早めに丁寧に書くと楽になります。
「とりあえず `unwrap()`」は、学習中の実験では使えます。
しかし教材の本筋では、なぜ失敗したかを返す練習をします。
`unwrap()` は失敗時にプログラムを止めます。
止めてよい場面もありますが、ユーザーに説明したい場面では不親切です。
`Result` で返すと、呼び出し元が判断できます。
国の仕組みにするなら、判断できる余地を残します。

告。`main` も `Result` を返せます。
解。`fn main() -> Result<(), Box<dyn std::error::Error>>` のような形にすると、`main` の中でも `?` を使いやすくなります。
`()` は、成功した時に特に返す値がないという印です。
空の報告書のようなものです。
`Box<dyn Error>` は、いろいろなエラーを一つの形で返したい時に使われます。
ただし最初は、章で指定された簡単なエラー型から始めれば十分です。

解。エラー文は、利用者への道案内です。
「失敗しました」だけでは、次に何をすればよいかわかりません。
「records/cave.txt を開けませんでした」のように、対象を入れると親切です。
「権限を確認してください」のように、次の行動を示すとさらに親切です。
ただし内部の詳細を出しすぎると危険な場合もあります。
教材では、原因を学ぶために少し詳しく出します。
運用では、ログとユーザー向け表示を分けます。

解。読み込み処理は、次章の共同体づくりにつながります。
洞窟の記録を読めるようになると、外に出る準備が整います。
外に出れば、名前を持つ仲間が増えます。
仲間が増えると、情報を覚える場所が必要になります。
そこで `struct` と `HashMap` の出番になります。
つまり Level 2 は単なるファイル読みではありません。
記録を読む国から、記録を持つ国へ進む橋です。

提案。`Result` を見たら、怖がらずに二本の道を描いてください。
成功したら何が手に入るか。
失敗したら誰に何を伝えるか。
その二本を関数の戻り値に書く。
これだけで、Rust のエラー処理はずっと優しくなります。

告。`map_err` や `match` は、失敗を言い換える時に使えます。
解。最初は `?` だけで十分です。
しかし、利用者にもっと分かりやすく伝えたい時があります。
その時は `match` で `Ok` と `Err` を分けて書けます。
`map_err` は、エラーの形だけを変えたい時に使えます。
今すぐ暗記する必要はありません。
大切なのは、失敗は捨てるものではなく、意味を添えて渡せるものだと知ることです。

提案。I/O のコードを書いたら、成功ファイルと存在しないファイルの両方で試してください。
成功だけでは、`Result` を学んだことになりません。
失敗した時の表示が読めるか。
呼び出し元へ自然に返せるか。
この確認が、次章の Store 設計を支える土台になります。

## 初出用語・関数の説明

- `use`: モジュールや型を現在のスコープに持ち込むキーワード。
- `std::fs`: 標準ライブラリのファイルシステム操作モジュール。
- `std::io`: 入出力と I/O エラーを扱う標準ライブラリのモジュール。
- `Result<T, E>`: 成功なら `Ok(T)`、失敗なら `Err(E)` を表す型。
- `io::Error`: ファイルやネットワークなどの I/O 失敗を表すエラー型。
- `std::env::args`: コマンドライン引数を取得する関数。
- `nth(1)`: イテレータから 2 番目の要素を取り出すメソッド。
- `expect`: `Option` や `Result` から値を取り出し、失敗時に指定メッセージで停止するメソッド。
- `?`: 失敗時にエラーを呼び出し元へ返す演算子。
- `Ok(())`: 成功したが返す値が特にないことを表す。

### 用語補講: I/O と失敗の言葉をほどく

- `Result<T, E>`: 成功か失敗かを表す型です。
  成功なら `Ok(T)`、失敗なら `Err(E)` になります。
  `T` は成功時に得られる値の型です。
  `E` は失敗時に得られるエラーの型です。

- `Ok`: `Result` の成功側です。
  `Ok(content)` なら、処理が成功して `content` が得られたという意味です。
  成功した中身は、`match` や `?` で取り出せます。
  成功も値として扱えるのが Rust の特徴です。

- `Err`: `Result` の失敗側です。
  `Err(error)` なら、処理が失敗して `error` が理由を持っています。
  失敗理由を捨てずに返すと、呼び出し元が判断できます。
  I/O では `Err` が普通に起こる前提で設計します。

- `?`: `Result` の成功値を取り出し、失敗なら早く返す演算子です。
  成功時は中身だけが次の処理へ進みます。
  失敗時は現在の関数からそのエラーを返します。
  `?` を使う関数は、失敗を返せる戻り値にしておきます。

- `unwrap()`: 成功なら中身を取り出し、失敗ならプログラムを止めます。
  実験やテスト準備では便利な場面があります。
  しかし、ファイル読み込みの本筋では失敗を丁寧に扱う方が安全です。
  「ここで止まってよい」と説明できる時だけ使います。

- `std::fs`: ファイルやディレクトリを扱う標準ライブラリのモジュールです。
  ファイル読み込み、書き込み、削除、ディレクトリ作成などがあります。
  この章では `read_to_string` が中心です。
  後の章では探索や WAL でも関係します。

- `std::fs::read_to_string`: ファイル全体を読んで `String` にする関数です。
  小さなテキストファイルを読むのに便利です。
  失敗する可能性があるため、戻り値は `Result` です。
  大きなファイルを扱う時は、少しずつ読む設計も考えます。

- `std::io::Error`: 入出力で失敗した理由を表す型です。
  ファイルがない、権限がない、読み取りに失敗した、などを表せます。
  表示すると原因の手がかりになります。
  ただし利用者向けには、対象ファイル名などの文脈を添えると親切です。

- `()`: ユニット型です。
  成功したが返す値は特にない、という時に使います。
  `Result<(), E>` は「成功なら何も返さず、失敗ならエラーを返す」という意味です。
  空っぽでも意味のある型だと考えてください。

- `match`: 値の形によって処理を分ける構文です。
  `Result` なら `Ok` と `Err` を分けて書けます。
  `Option` なら `Some` と `None` を分けられます。
  分岐漏れをコンパイラが教えてくれるのが強みです。

- `map_err`: `Result` の失敗側だけを別の形に変えるメソッドです。
  エラーに文脈を足したい時に使えます。
  最初から使いこなす必要はありません。
  「エラーも値なので変換できる」と知っておけば十分です。

### 大賢者による追加解説

『告。I/O の基本構造を解説します』

I/O は Input/Output の略です。

ファイルを読むことは Input です。

画面へ表示することは Output です。

ネットワークから受け取ることも Input です。

ネットワークへ送ることも Output です。

I/O は外部世界と接続するため、失敗が常にあります。

Rust では、多くの I/O 操作が `Result` を返します。

`std::fs::read_to_string` は、ファイル全体を文字列として読む便利な関数です。

小さなファイルを読むには分かりやすい選択です。

大きなファイルを一気に読むと、メモリを多く使う可能性があります。

その場合は `File` と `BufReader` を使い、一部ずつ読む判断が出てきます。

`std::io::Error` は、I/O 失敗を表す標準ライブラリのエラー型です。

存在しないファイル、権限不足、読み取り中断などの情報を持ちます。

`?` は、`Result` が `Err` ならそのまま返し、`Ok` なら中身を取り出します。

これにより、成功の流れを読みやすく書けます。

ただし、`?` は失敗を消していません。

関数の戻り値として、呼び出し側へ運んでいます。

`match` は、`Ok` と `Err` を明示的に分岐する方法です。

失敗時にメッセージを変える。

別の処理へ切り替える。

エラー種別ごとに対応を変える。

そうした場面では `match` が役立ちます。

### コードで見る記録読み

最小の読み込みは次の形です。

```rust
use std::fs;

fn read_record(path: &str) -> Result<String, std::io::Error> {
    fs::read_to_string(path)
}
```

`use std::fs;` は、`std::fs` を短い名前で使うための宣言です。

`read_record` は、パスを借りて、内容を所有する `String` として返します。

失敗した場合は `std::io::Error` を返します。

呼び出し側で処理するなら、次のようにします。

```rust
fn main() {
    match read_record("data/message.txt") {
        Ok(text) => println!("{}", text),
        Err(err) => eprintln!("read failed: {}", err),
    }
}
```

`eprintln!` は標準エラー出力へ表示します。

通常の結果ではなく、エラーや診断情報を出すときに使います。

CLI では、標準出力と標準エラーを分けることが大切です。

利用者が通常出力をファイルへ保存しても、エラーが混ざらないようにするためです。

### 初出用語・関数の追加説明

- I/O: Input/Output。ファイル、画面、ネットワークなど外部との入出力。
- `std::fs`: ファイルやディレクトリを扱う標準ライブラリのモジュール。
- `fs::read_to_string`: ファイル全体を UTF-8 文字列として読む関数。
- `std::io`: 入出力に関する型やトレイトを含む標準ライブラリのモジュール。
- `std::io::Error`: I/O 操作の失敗を表す型。
- `Ok`: `Result` の成功側。
- `Err`: `Result` の失敗側。
- `?`: 失敗を呼び出し元へ返し、成功時は中身を取り出す演算子。
- `match`: 値の形に応じて処理を分ける構文。
- `use`: 長いパスを短く使うための宣言。
- `eprintln!`: 標準エラー出力へ改行付きで表示するマクロ。
- 標準エラー出力: エラーや診断情報を出すための出力先。
- UTF-8: Rust の `String` が前提にする文字エンコーディング。
- パニック: プログラムが回復不能な状況として実行を中断すること。
- 委譲: 自分で処理せず、上位の呼び出し元へ処理判断を渡すこと。
