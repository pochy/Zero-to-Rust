## 智慧之王による解説

『告。Level 7 の目的は、中規模コードに耐えるレイヤー分割と並行処理です』

`Arc<T>` は、複数スレッドから同じ値を共有するための参照カウント付きスマートポインタです。`Mutex<T>` は、同時に 1 つの処理だけが中身にアクセスできるように保護します。

`Arc<Mutex<Store>>` は、複数スレッドで `Store` を共有しつつ、更新時にロックする典型的な形です。

『解。ただし、これは便利な万能薬ではありません』

危険な設計:

```rust
type SharedEverything = Arc<Mutex<App>>;
```

より良い設計:

```rust
type SharedStore = Arc<Mutex<Store>>;
```

共有対象を小さくし、ロック範囲を短くします。ロック中にネットワーク I/O をすると、他の処理が待たされます。

`mpsc` は、複数の送信者から 1 つの受信者へメッセージを送るチャンネルです。スレッドプールでは、ジョブをキューへ送り、ワーカーが受け取って実行します。

## 初出用語・関数の説明

- `std::sync::Arc`: 複数所有を可能にするスレッド安全な参照カウント型。
- `std::sync::Mutex`: 共有データを排他制御する型。
- `std::sync::RwLock`: 複数読み取り、単一書き込みを制御するロック。
- `std::sync::mpsc`: メッセージ送信用のチャンネルを提供するモジュール。
- `std::thread`: OS スレッドを扱う標準ライブラリのモジュール。
- `thread::spawn`: 新しいスレッドを起動する関数。
- `JoinHandle`: 起動したスレッドの終了を待つためのハンドル。
- `Box<dyn FnOnce()>`: 実行できる処理をヒープ上に置き、型を抽象化したもの。
- `Send`: 値を別スレッドへ送れることを示す trait。
- `'static`: 参照が短命な外部データに依存しないことを示すライフタイム条件。
- ロック範囲: `Mutex` や `RwLock` を保持している期間。短いほど他処理を待たせにくい。
- graceful shutdown: 処理中の仕事を壊さず、順序立てて終了する設計。
