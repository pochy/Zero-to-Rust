## 智慧之王による解説

『告。最終課題の目的は、これまでの Level を 1 つの設計へ統合することです』

推奨レイヤー:

```text
server 層      TCP/HTTP 接続
protocol 層    コマンドとレスポンス
store 層       データ管理と TTL
persist 層     WAL
config 層      設定
error 層       エラー型
```

データの流れ:

```text
TCP で 1 行受信
protocol が Command に変換
store が Command を実行
persist が必要な操作を WAL に追記
response を wire format に変換
TCP で返す
ログと metrics を更新
```

『解。重要なのは、どの層が何を知らないかです』

`store` は TCP を知りません。`protocol` は `HashMap` の内部を知りません。`persist` はクライアント接続を知りません。これにより、テストと変更が容易になります。

WAL 書き込みに失敗した場合、保存成功として `OK` を返すべきではありません。復旧性を保証するなら、永続化に失敗した操作は成功扱いにしない方針を明記します。

## 初出用語・関数の説明

- TTL: Time To Live。キーが有効でいられる残り時間。
- `EXPIRE`: キーに有効期限を設定するコマンド。
- `GET /health`: HTTP でサーバーの生存状態を返す管理エンドポイント。
- `GET /metrics`: 処理件数やエラー数などの簡易指標を返す管理エンドポイント。
- `GET /keys`: 現在のキー一覧を返す管理エンドポイント。
- Metrics: システム状態を数値で観測するための指標。
- config 層: 起動アドレス、ワーカー数、保存先などの設定を扱う層。
- error 層: エラー型と変換方針をまとめる層。
- persist 層: WAL など永続化を担当する層。
- 統合テスト: TCP、Store、WAL など複数部品を組み合わせて確認するテスト。
- 運用ドキュメント: 起動、監視、復旧、制限を利用者や運用者へ伝える文書。
