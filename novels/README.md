# Rust 転生譚: 標準ライブラリで国を作るチュートリアル

このフォルダは、[TUTORIAL.md](../TUTORIAL.md) の内容を、スライム転生、内なる解析者、仲間集め、国家運営、魔王化、世界規模の危機という成長曲線に置き換えて読むストーリー風チュートリアルです。

[TENSURA.md](../TENSURA.md) で整理されている「弱い存在として目覚める」「捕食と解析で能力を得る」「名付けで仲間を増やす」「共同体を国家にする」「魔王として責任を負う」「神話級の危機へ至る」という構造を、Rust 学習に対応させています。

原作本文や特定作家の文体を再現するものではありません。ここでは、リムル風の主人公が、Rust の所有権、借用、`Result`、I/O、ネットワーク、テスト、並行処理、WAL、境界チェックを、ひとつずつ国づくりの課題として解いていく教材用のオリジナルシナリオにしています。

## 物語の約束

主人公は洞窟で目覚めたスライムです。目も耳も手足もなく、あるのは内なる声と、厳格な Rust コンパイラだけです。

```text
所有者を決める。
借りる範囲を決める。
失敗を隠さない。
共有するなら守る。
状態は復元できるように残す。
最後に、設計判断を説明する。
```

大賢者は、序盤ではコンパイラ、標準ライブラリ docs、百科事典のようにふるまいます。中盤以降は智慧之王へ進化し、設計レビュー、失敗分析、運用判断まで踏み込む参謀になります。

Rust も同じです。曖昧な所有権、握りつぶしたエラー、巨大な `main.rs`、広すぎるロック、復旧できない永続化。どれも、国づくりでは後で災厄になります。

この小説版では、それらをテンペスト建国の事件として扱います。

## 増補版の読み方

この `novels/` は、教材本文を置き換えるものではありません。

まず `TUTORIAL.md` と `levels/` で、実際の到達目標を確認します。

その後で各話を読むと、Rust の概念が「事件」「会議」「失敗」「復旧」として記憶に残るように作っています。

章ごとに、次の三つを意識してください。

- 物語で何が起きたか。
- Rust では何の概念に対応しているか。
- 自分ならどこに責務を置くか。

主人公はスライム型の学習者です。

大賢者は、序盤でコンパイラ、Rust docs、百科事典のように振る舞います。

智慧之王は、中盤以降で設計レビュー、標準ライブラリの統合判断、失敗分析、運用判断を担当します。

この二つの声は、単なる説明役ではありません。

Rust を学ぶときに頭の中へ育てるべき、もう一人のレビュアーです。

「この値は誰のものか」

「この失敗を握りつぶしてよいか」

「このロック範囲は長すぎないか」

「復旧できない設計を、本当に本番に出すのか」

そう問い続ける存在として読んでください。

## 章別の読みどころ

### 00 所有権転生

最初の章は、Rust を文法ではなく責任の物語として扱います。

スライムとして何も持たない状態から始めることで、「値を持つ」とは何かを確認します。

`clone` や `unwrap` を使う前に、なぜそれが設計判断なのかを考える章です。

### 01 最初のスキル

`println!` で言葉を出すだけの小さな成功を、スキル発動として描きます。

`String` と `&str` の違いは、所有する言葉と借りた言葉の違いとして扱います。

関数へ渡したあとに値が使えなくなる驚きを、所有権移動の事件として読む章です。

### 02 記録を読む

ファイルを読むことは、世界の記録へ触れることです。

ここでは `Result` と `?` を、失敗を仲間へ報告する仕組みとして学びます。

エラーを隠すのではなく、進路を変えるための情報として返す章です。

### 03 名付けと Store

仲間へ名を与える物語を、データ構造の設計へ置き換えます。

`struct` は国民台帳の欄、`enum` は命令の型、`HashMap` は名前から値を探す広場です。

単に保存するだけでなく、どの責務をどこに置くかを考えます。

### 04 森の探索

ディレクトリ探索を、ジュラの森の調査として扱います。

`Path` と `PathBuf` の違い、再帰、部分失敗、CLI の使いやすさを一つの遠征にまとめます。

全部成功しないと失敗なのか、一部を報告して続けるべきなのかがテーマです。

### 05 通信網

TCP を使った通信を、テンペストの街道と伝令網として扱います。

`TcpListener` は門番、`TcpStream` は使者、`BufReader` は巻物を一行ずつ読む係です。

プロトコルは、誰が見ても同じ意味になる約束として描きます。

### 06 災厄後のテスト

「動いた」という報告だけでは国を守れません。

テストは疑うためではなく、約束を残すための仕組みです。

智慧之王が登場し、感覚ではなく再現可能な検証へ学習者を引き上げます。

### 07 スレッドプール

単独の英雄ではなく、組織として処理する段階です。

`Arc`、`Mutex`、`RwLock` を、共有資源と会議室の鍵として扱います。

速さより先に、共有状態の責務とロック範囲を考えます。

### 08 WAL と運用

開国すれば、使われ、落ち、復旧を迫られます。

`WAL` は、事故のあとで国の記憶を取り戻すための記録です。

環境変数、ログ、設定、復旧手順を、外交と運用の言葉で扱います。

### 09 究極能力

標準ライブラリだけで何を作るか、どこから外部クレートを採用するかを考えます。

DNS、SHA、Lisp、圧縮などの候補は、強い力ほど境界を見極める必要があることを示します。

`unsafe` は禁忌ではなく、責任を説明できる場合だけ扱う領域として登場します。

### 10 最終課題

ここまでの学習を、TCP KVS という中核システムへ統合します。

TTL、WAL、HTTP 管理、ログ、テスト、復旧を別々の機能ではなく一つの国家運営として設計します。

完成条件は「動く」ではなく「説明でき、壊れ方を知り、直せる」ことです。

## 登場する内なる声

### 大賢者

大賢者は、初学者にとってのコンパイラと公式ドキュメントの声です。

知らない用語を見つけたら、短く定義します。

危ない省略を見つけたら、警告します。

読者が「まあ動くからいいか」と流しそうな場所で、立ち止まるよう促します。

### 智慧之王

智慧之王は、経験を積んだあとに必要になるレビューの声です。

単に正しい API を答えるのではなく、どの設計が運用に耐えるかを評価します。

テスト、失敗分類、ロック範囲、復旧、ログ、境界設計を扱います。

「その判断を説明できますか」と問い、曖昧な実装を仕様へ変えます。

## 学習者への約束

初めて登場する用語、型、関数、標準ライブラリ項目は、章内で短く説明します。

説明は百科事典的に長くしません。

その章で使うために必要な意味へ絞ります。

深追いしたい場合は、対応教材と公式 docs を読んでください。

物語はあくまで理解の足場です。

最終的には、読者自身がコードを書き、エラーを読み、設計を説明する必要があります。

この読み物のゴールは、Rust を「怖い言語」から「責務を明確にする言語」へ変えることです。
