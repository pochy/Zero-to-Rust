## 会話・独白パート

俺は大賢者に聞いた。

「文字列って、どうやって持つんだ？」

『解。所有する文字列には `String` を使用します。借りるだけの文字列には `&str` を使用します』

「所有する名前と、借りる名前が違うってこと？」

『肯定。例えば、名札を作って持つなら `String`。誰かの名札を読むだけなら `&str` です』

暴風竜が鼻を鳴らす。

「名前とは魂に刻むものだ。借り物ではつまらぬぞ」

「いや、API の話をしてるんだ」

『提案。まず小さな例で確認します』

```rust
fn main() {
    let name = String::from("Rust");
    borrow_name(&name);
    take_name(name);
}

fn borrow_name(value: &str) {
    println!("borrowed: {}", value);
}

fn take_name(value: String) {
    println!("owned: {}", value);
}
```

「`borrow_name(&name)` は、名前を貸してるだけ？」

『解。はい。`name` の所有者は `main` のままです』

「`take_name(name)` は？」

『解。`String` の所有権が `take_name` に移動します。その後、元の `name` は使えません』

暴風竜が楽しそうに笑った。

「なるほど。名を渡せば、そやつのものになる。名を見せるだけなら、自分のもののままか」

「そう言われると、異世界っぽいな」

「でもさ、大賢者」

『告。質問を受け付けます』

「`String` を渡したら、もう使えないって、やっぱり不便じゃないか？」

『解。不便に見えるのは、所有権の移動を代入やコピーと混同しているためです』

「コピーじゃないのか」

『肯定。`String` はヒープ上に文字データを持ちます。値には、そのデータへのポインタ、長さ、容量が含まれます』

「ヒープって？」

『解。実行時に必要な分だけ確保するメモリ領域です。伸び縮みするデータを置く場所と考えてください』

ヴェルドラが割り込んだ。

「ふむ。洞窟の外に倉庫を持つようなものか」

『肯定。二重解放などの危険があります』

『解。所有者を一人に保つためです』

『肯定』

## 大賢者による解説

『告。Level 1 の目的は、Rust を動かし、所有権の移動を体験することです』

`String` は、ヒープに確保された文字列データを所有します。関数に `String` をそのまま渡すと、所有権が移動します。

`&str` は文字列スライスです。文字列を所有せず、既存の文字列を読むための参照として使います。

『解。関数の引数型は、その関数が値を所有したいのか、読むだけでよいのかを表します』

悪い癖は、コンパイルエラーを避けるためだけに `clone()` を使うことです。`clone()` は所有するデータを複製します。必要な場面では正しい判断ですが、理由なく使うと責任範囲が曖昧になります。

```rust
fn print_name(value: &str) {
    println!("{}", value);
}
```

表示するだけなら、所有権を受け取る必要はありません。

### 補講: 最初の出力を小さく分解する

告。`println!` は、最初に覚える観測魔法です。
解。プログラムは、動いているだけでは中で何が起きたかわかりません。
`println!` は、値を画面に出して、今の状態を観測するための道具です。
末尾の `!` はマクロである印です。
マクロは、普通の関数呼び出しより前の段階でコードを展開する仕組みです。
今は「表示用の便利な構文」くらいに受け取って大丈夫です。
大事なのは、表示が所有権を奪うとは限らないことです。

解。`String` は、育つ文字列です。
`String::from("Rimuru")` のように作ると、必要に応じて中身を増やせる文字列になります。
この文字列はヒープという領域にデータを置きます。
ヒープは、コンパイル時に大きさが決まらないデータを置く場所です。
だから `String` には所有者が必要です。
誰が片付けるのかをはっきりさせないと、メモリ管理が危険になるからです。

解。`&str` は、文字列の一部または全体を見る窓です。
`"hello"` のような文字列リテラルは、多くの場合 `&'static str` として扱われます。
`static` は、プログラムの実行中ずっと存在するという意味です。
ただし、最初からライフタイム記法を全部覚える必要はありません。
まずは `String` は所有する文字列、`&str` は借りて読む文字列、と分ければ十分です。
関数の引数に `&str` を使うと、`String` からも文字列リテラルからも渡しやすくなります。

告。`let` は束縛です。
解。`let name = String::from("Rimuru");` は、`name` という札に値を結びます。
この札が所有者になります。
ただの箱というより、責任者の名札だと考えると自然です。
`let other = name;` とすれば、責任者が `other` に変わります。
その後の `name` は、元の値を担当していません。
だから使うとコンパイラが止めます。

提案。関数へ渡す時は、三つの問いで判断してください。
値を相手に完全に渡したいのか。
相手に読ませたいだけなのか。
相手に書き換えさせたいのか。
完全に渡すなら所有権を渡します。
読むだけなら `&T` を渡します。
書き換えさせるなら `&mut T` を渡します。
この三択が見えると、関数シグネチャが急に読みやすくなります。

解。`format!` と `println!` の違いも早めに知ると安心です。
`println!` は画面に出します。
`format!` は整形した文字列を `String` として作ります。
つまり `format!` の結果には所有者が必要です。
たとえば `let line = format!("name={}", name);` なら、`line` が新しい `String` の所有者です。
表示だけしたいなら `println!`。
後で使う文字列を作りたいなら `format!`。
そう分けると迷いにくくなります。

告。`{}` は表示場所です。
解。`println!("name={}", name);` の `{}` には、後ろの `name` が入ります。
これは文字列補間のように見えますが、Rust ではフォーマット指定として処理されます。
値を表示するには、その型が表示方法を知っている必要があります。
普通の表示は `Display`、デバッグ表示は `Debug` というトレイトが関係します。
`{:?}` を使うと、開発中に見やすい形で出せることがあります。
ただし、学び始めは `{}` と `{:?}` の使い分けを知っておけば十分です。

解。所有権の移動は、出力のあとにも関係します。
表示したあとに値が使えるなら、表示は値を借りただけです。
関数に渡したあとに使えないなら、所有権が移動した可能性があります。
この観察を小さなコードで試すと、Rust の感覚が早く育ちます。
エラーを避けるだけでなく、なぜ避けられたのかを見ます。
Level 2 では、この観察をファイル読み込みの結果に広げます。

提案。今日の合言葉は「表示して、所有者を見る」です。
まず名前を作る。
表示する。
別の変数へ渡す。
もう一度表示しようとして、何が起きるか見る。
その結果を、コンパイラの言葉と照らし合わせます。
小さな失敗を洞窟の壁に刻むほど、次の探索は安全になります。

告。最後に、成功体験を小さく固定します。
解。画面に一行出せたなら、Rust はもう動いています。
次に見るのは、値がどこへ渡ったかです。
表示と所有権を同時に追えれば、Level 2 のファイル読み込みも怖くありません。
読めた文字列も、読めなかった理由も、どちらも値として扱っていきます。

## 初出用語・関数の説明

- `fn main()`: Rust プログラムの入口になる関数。
- `println!`: 標準出力に文字列を表示するマクロ。末尾に改行を付ける。
- `let`: 変数束縛を作るキーワード。
- `String`: 伸長可能で所有権を持つ文字列型。
- `String::from`: 文字列リテラルなどから `String` を作る関連関数。
- `&str`: 文字列を所有せずに読むための文字列スライス。
- `&name`: `name` を借用する表記。
- `clone()`: 値を複製するメソッド。設計理由がある場合に使う。

### 用語補講: 表示と文字列を丁寧に読む

- `println!`: 画面へ文字を出すマクロです。
  `!` が付くものはマクロ呼び出しです。
  値を観測するためによく使います。
  表示したからといって、必ず所有権を奪うわけではありません。

- マクロ: コンパイルの途中でコードを展開する仕組みです。
  関数に似て見えますが、普通の関数より柔軟な構文を扱えます。
  `println!` や `format!` は代表例です。
  最初は「便利な特別構文」くらいの理解で十分です。

- `String`: 所有する文字列です。
  後から文字を追加でき、ヒープにデータを持ちます。
  所有者が必要なので、関数へそのまま渡すとムーブすることがあります。
  長く使う文字列や作った文字列には `String` がよく使われます。

- `String::from`: 文字列リテラルなどから `String` を作る関連関数です。
  `String::from("hello")` のように書きます。
  新しい `String` が作られ、その所有者が変数になります。
  似た書き方に `"hello".to_string()` もあります。

- `&str`: 文字列を借りて読むための型です。
  文字列スライスとも呼ばれます。
  `String` の中身を読む時にも、文字列リテラルを読む時にも使えます。
  表示するだけの関数なら、引数を `&str` にすると使いやすいです。

- 文字列リテラル: `"hello"` のようにソースコードへ直接書く文字列です。
  多くの場合、プログラム中ずっと存在する読み取り専用の文字列として扱われます。
  型としては `&str` と見れば学習初期は十分です。
  変更したいなら `String` に変換します。

- `format!`: 文字列を組み立てて `String` として返すマクロです。
  画面には出さず、値として持ちます。
  後でログに渡したい、ファイルに書きたい、応答にしたい時に使います。
  `println!` は表示、`format!` は作成、と分けると覚えやすいです。

- `clone()`: 値を明示的に複製するメソッドです。
  所有権エラーを避けるためだけに乱用すると、設計が曖昧になります。
  ただし、同じ内容を本当に二箇所で所有したいなら正しい選択です。
  使う時は「なぜ複製が必要か」を言葉にします。

- `Display`: `{}` で表示するためのトレイトです。
  利用者向けに自然な表示をしたい型が実装します。
  まだ自作する必要はありませんが、エラーで名前を見ることがあります。
  表示できない型は、`{:?}` のデバッグ表示を試す場合があります。

- `Debug`: `{:?}` で開発者向けに表示するためのトレイトです。
  構造体や enum の中身を確認する時に便利です。
  `#[derive(Debug)]` で自動実装できる場合があります。
  学習中の観測に役立つ、と覚えておくと十分です。

### 大賢者による追加解説

『告。Level 1 の中心概念を整理します』

`println!` は、標準出力へ文字列を表示するためのマクロです。

`!` が付いているため、通常の関数ではなくマクロ呼び出しです。

`println!("text")` は、末尾に改行を付けて表示します。

`print!("text")` は、改行を付けずに表示します。

`{}` は、値を表示用に埋め込む場所です。

この仕組みはフォーマット文字列と呼ばれます。

次に、`let` は変数束縛を作ります。

Rust では、変数はデフォルトで不変です。

変更したい場合は `mut` を付けます。

ただし、何でも `mut` にすると責任範囲が広がります。

変更する理由がある場所だけ `mut` にしてください。

`String` は所有する文字列です。

`String::from("abc")` は、文字列リテラルから `String` を作ります。

`&str` は文字列スライスへの参照です。

関数が読むだけなら、`&str` を受け取る設計がよく使われます。

`String` を引数にすると、その関数は文字列を所有します。

所有する必要がないのに所有させると、呼び出し側が値を失うことがあります。

これが Level 1 の大きな罠です。

「表示するだけの関数」が `String` を奪う必要はありません。

「保管する関数」なら `String` を受け取る理由があります。

API の引数型は、関数の責務を表します。

### 小さなコード劇場

次のコードでは、`name` の所有権が移動します。

```rust
fn take_name(name: String) {
    println!("{}", name);
}

fn main() {
    let name = String::from("Slime");
    take_name(name);
    // println!("{}", name); // ここでは使えない
}
```

このコードで大切なのは、エラーそのものではありません。

`take_name` が「名前を消費する関数」になっていることです。

消費したくないなら、借用にします。

```rust
fn show_name(name: &str) {
    println!("{}", name);
}

fn main() {
    let name = String::from("Slime");
    show_name(&name);
    println!("{}", name);
}
```

この場合、`show_name` は名前を借りて表示するだけです。

呼び出し後も、`name` は使えます。

物語で言えば、広場で名前を読み上げただけです。

戸籍そのものを持ち去ってはいません。

### 初出用語・関数の追加説明

- `println!`: 標準出力へ値を表示し、最後に改行を入れるマクロ。
- `print!`: 標準出力へ値を表示するが、改行は自動では入れないマクロ。
- マクロ: コンパイル前後の段階でコードを展開する仕組み。呼び出し名に `!` が付く。
- フォーマット文字列: `"name: {}"` のように、表示内容と埋め込み位置を指定する文字列。
- `{}`: `Display` 形式で値を表示するためのプレースホルダ。
- `{:?}`: `Debug` 形式で値を表示するためのプレースホルダ。
- `let`: 変数束縛を作るキーワード。
- `mut`: 変数や参照を変更可能にするキーワード。
- `fn`: 関数を定義するキーワード。
- 引数: 関数へ渡す値。
- 戻り値: 関数から呼び出し元へ返す値。
- `String::from`: 文字列リテラルなどから所有する `String` を作る関連関数。
- 文字列リテラル: ソースコードに直接書かれた固定文字列。
- ヒープ: 実行中に必要な量を確保するメモリ領域。
- 標準出力: プログラムが通常の結果を出す先。
