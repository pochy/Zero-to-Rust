}

### 補講: 探索 CLI を安心して設計する

告。`Path` は、場所そのものではなく、場所を表す名前です。
解。ファイルやディレクトリは、実際には OS が管理しています。
Rust の `Path` は、その場所へ向かうための道筋を表します。
文字列に似ていますが、ただの `String` ではありません。
OS によって区切り文字や扱える文字が違うためです。
`Path` を使うと、「これはファイルパスです」という意図を型で示せます。
初心者はパスを文字列でつなげがちですが、まず `Path` の道具を使う習慣をつけると安全です。

解。`PathBuf` は、所有できるパスです。
`Path` は借用で扱うことが多い型です。
一方、探索しながら新しいパスを作って保持したい時は `PathBuf` が便利です。
`String` と `&str` の関係に少し似ています。
`PathBuf` は自分でパスのデータを持ちます。
`Path` はどこかにあるパスを読むために借ります。
この区別も、所有権の学びの延長です。

告。`read_dir` は失敗する探索です。
解。ディレクトリが存在しないかもしれません。
権限がなくて読めないかもしれません。
探索中にファイルが消えるかもしれません。
だから `std::fs::read_dir` は `Result` を返します。
さらに、ディレクトリの中の各エントリを読む時にも失敗する可能性があります。
「最初に読めたから全部安全」とは限りません。
森の道は、歩いている途中で崩れることがあります。

解。再帰探索は、自分と同じ仕事を小さな場所で繰り返す方法です。
ディレクトリの中にファイルがあれば調べます。
ディレクトリがあれば、その中をまた同じように調べます。
この形を関数で表すと、関数が自分自身を呼びます。
ただし深すぎる階層では、呼び出しが多くなりすぎる危険もあります。
教材では素直な再帰で学びます。
運用では深さ制限や循環対策も考えます。

提案。探索では「全部成功」だけを前提にしないでください。
一つのファイルが読めなくても、他のファイルは調べられるかもしれません。
これを部分失敗と呼びます。
部分失敗をエラーで即終了するか、警告として続行するかは設計判断です。
検索 CLI では、読めないファイルを `stderr` に報告し、読めた結果は `stdout` に出す設計がよくあります。
成功結果と警告を分けると、他のコマンドと組み合わせやすくなります。

解。`stdout` は標準出力です。
検索に見つかった行など、利用者が次の処理へ渡したい結果を出します。
`stderr` は標準エラーです。
警告や診断情報など、結果とは分けたい情報を出します。
この二つを分けると、コマンドラインの道具として扱いやすくなります。
たとえば結果だけをファイルに保存し、警告は画面に残すことができます。
小さな違いですが、プロの CLI では大事な作法です。

告。検索条件は、最初は単純でよいです。
解。`contains` は、文字列の中に指定した文字列が含まれるかを調べます。
たとえば `line.contains("magicule")` なら、その行に `magicule` があるか確認できます。
ただし大文字と小文字は区別されます。
日本語の表記ゆれや Unicode 正規化までは面倒を見ません。
最初から完全な検索エンジンを目指す必要はありません。
まず「入力を読み、行を調べ、結果を出す」流れを作ります。

解。`lines()` は、文字列を行ごとに見るための便利なメソッドです。
ファイル全体を `String` として読んだあと、`content.lines()` とすると行単位で処理できます。
行番号がほしい時は `enumerate()` を組み合わせます。
`enumerate()` は、要素に `0` から始まる番号を付けます。
利用者に表示する行番号は `1` 始まりにしたいことが多いので、表示時に `index + 1` とします。

## 初出用語・関数の説明

- `std::path::Path`: 借用されたパスを表す型。ファイルやディレクトリの位置を扱う。
- `std::path::PathBuf`: 所有するパスを表す型。検索結果として保持したい場合に使う。
- `lines()`: 文字列を行ごとに分割するメソッド。
- `enumerate()`: イテレータの各要素に 0 から始まる番号を付けるメソッド。
- `contains`: 文字列が指定したパターンを含むか調べるメソッド。
- `display()`: パスを表示用の形に変換するメソッド。
- 再帰探索: ディレクトリの中にあるディレクトリを、さらに同じ手順で探索する方法。
- ANSI エスケープ: 端末上で色や表示効果を付けるための制御文字列。
- 部分失敗: 全体処理の一部だけが失敗すること。失敗した箇所を記録し、可能なら処理を継続する。

### 用語補講: ファイル探索で出会う言葉

- `Path`: ファイルやディレクトリの場所を表す借用型です。
  ただの文字列ではなく、OS のパスとして扱う意図を示します。
  関数の引数に `&Path` を使うと、パスを所有せずに読めます。
  文字列連結でパスを作るより安全です。

- `PathBuf`: 所有できるパスです。
  探索しながら新しいパスを作ったり、リストに保存したりする時に使います。
  `String` と `&str` の関係に少し似ています。
  `PathBuf` は持つ、`Path` は借りる、と覚えると楽です。

- `read_dir`: ディレクトリの中身を読む関数です。
  戻り値は `Result` なので、失敗を扱う必要があります。
  ディレクトリがない、権限がない、途中で消えるなどがあり得ます。
  探索では、最初から部分失敗を想定します。

- `DirEntry`: `read_dir` で得られる各項目を表す型です。
  ファイルかディレクトリかを調べる入口になります。
  `entry.path()` でその項目のパスを取得できます。
  ただし、項目を読む時点でも失敗する可能性があります。

- 再帰: 関数が自分自身を呼び出すことです。
  ディレクトリの中にディレクトリがある場合、同じ処理を繰り返せます。
  分かりやすい反面、深すぎる階層には注意します。
  本格運用では深さ制限や循環対策を検討します。

- `contains`: 文字列が別の文字列を含むか調べるメソッドです。
  簡単な検索に向いています。
  大文字小文字は区別されます。
  高度な検索や正規表現は、この教材の範囲外です。

- `lines`: 文字列を行ごとに見るメソッドです。
  ファイル内容を検索する時に便利です。
  行末の改行は含まれません。
  行番号が必要なら `enumerate` と組み合わせます。

- `enumerate`: イテレータの各要素に番号を付けるメソッドです。
  番号は `0` から始まります。
  画面表示で `1` 始まりにしたいなら `index + 1` にします。
  小さな補正ですが、利用者にとっては大事です。

- `stdout`: 標準出力です。
  検索結果のように、次の処理へ渡したい情報を出します。
  コマンドを組み合わせる時に重要です。
  成功結果はできるだけここへ出します。

- `stderr`: 標準エラーです。
  警告や診断情報を出します。
  結果とは分けたい情報に使います。
  部分失敗を報告しながら探索を続ける時に役立ちます。

- `HashSet`: 値の集合を表すコレクションです。
  「この値を見たか」を調べるのに向いています。
  再帰探索の循環対策で候補になります。
  `HashMap` がキーから値を探すのに対し、`HashSet` は存在確認が中心です。

### 大賢者による追加解説

`Path` は、ファイルシステム上のパスを表す借用型です。

多くの場合、関数の引数には `&Path` を使います。

`PathBuf` は、所有するパスです。

パスを組み立てる、保存する、返す場合に使います。

`std::fs::read_dir` は、ディレクトリ内の項目を読む関数です。

戻り値は `Result<ReadDir, std::io::Error>` です。

ディレクトリが存在しない。

権限がない。

途中で読み取りに失敗する。

そうした可能性があるため `Result` です。

`DirEntry` は、ディレクトリ内の一項目を表します。

`entry.path()` で、その項目の `PathBuf` を取得できます。

`path.is_dir()` は、パスがディレクトリかどうかを調べます。

`path.is_file()` は、パスが通常ファイルかどうかを調べます。

`path.extension()` は、拡張子を取り出します。

戻り値は `Option<&OsStr>` です。

拡張子がない可能性があるため `Option` になります。

`OsStr` は、OS の文字列表現を扱う型です。

パスやファイル名は、常に普通の UTF-8 文字列とは限りません。

そのため、Rust は専用型で扱います。

### 探索アルゴリズムの形

探索関数の考え方は単純です。

```rust
fn visit(path: &Path) -> Result<(), std::io::Error> {
    if path.is_dir() {
        for entry in std::fs::read_dir(path)? {
            let entry = entry?;
            visit(&entry.path())?;
        }
    } else if path.is_file() {
        println!("{}", path.display());
    }
    Ok(())
}
```

この例は分かりやすいですが、実用上は検討が必要です。

`entry?` で項目読み取りに失敗したら、全体を止めます。

それでよい CLI もあります。

しかし、検索 CLI では、読めない場所を報告しつつ続行したいことがあります。

その場合、エラーを `Vec` に集める設計もあります。

```text
見つかったファイル一覧:
読み取れなかったパス一覧:
終了コード:
```

終了コードも設計対象です。

完全成功なら `0`。

検索対象なしでも成功とみなすのか。

部分失敗なら `1` にするのか。

CLI は、他のプログラムから呼ばれることもあります。

人間に読める表示だけでなく、機械が判断できる結果も考えます。

### 検索条件を設計する

探索するだけでは、森を全部歩くだけです。

検索 CLI には条件が必要です。

名前に含まれる文字。

拡張子。

ファイルサイズ。

更新日時。

本文に含まれるキーワード。

最初は、名前検索だけで十分です。

次に拡張子を加えます。

本文検索は I/O が増えるため、後で検討します。

こうして段階を分けるのが大切です。

最初から万能検索を作ろうとすると、責務が混ざります。

探索。

条件判定。

表示。

エラー集約。

それぞれを小さく分けると、後のテストが楽になります。

### 初出用語・関数の追加説明

- `Path`: 借用されたファイルシステムパスを表す型。
- `PathBuf`: 所有するファイルシステムパスを表す型。
- `std::path`: `Path` や `PathBuf` を含む標準ライブラリのモジュール。
- `std::fs::read_dir`: ディレクトリ内の項目を読む関数。
- `DirEntry`: ディレクトリ内の一項目を表す型。
- `is_dir`: パスがディレクトリか調べるメソッド。
- `is_file`: パスが通常ファイルか調べるメソッド。
- `extension`: パスの拡張子を取り出すメソッド。
- `display`: パスを表示用の形に変換するメソッド。
- `OsStr`: OS 固有の文字列表現を扱う型。
- 再帰: 関数が自分自身を呼び、同じ処理を階層へ適用する方法。
- 部分失敗: 全体の一部だけが失敗し、残りは処理できる状態。
- 終了コード: CLI が成功や失敗を呼び出し元へ伝える数値。
