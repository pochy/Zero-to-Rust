俺は検索の最小形を示した。

```rust
use std::fs;
use std::io;
use std::path::Path;

fn search_file(path: &Path, pattern: &str) -> Result<(), io::Error> {
    let content = fs::read_to_string(path)?;

    for (index, line) in content.lines().enumerate() {
        if line.contains(pattern) {
            println!("{}:{}: {}", path.display(), index + 1, line);
        }
    }

    Ok(())
}
```

森の中で、薬草の名前を含む古い標識を探す。標識が読めれば記録する。読めなければ、理由を残して次へ進む。

それが、探索の基本だった。

## 大賢者による解説

『告。Level 4 の目的は、I/O、文字列処理、再帰探索、表示を分けて考えることです』

検索 CLI では、次の責務を分離します。

```text
引数解析
探索対象の決定
ファイル読み込み
検索
結果の表示
エラーの扱い
```

`Path` と `PathBuf` を使う理由は、パスを単なる文字列ではなく、ファイルシステム上の位置として扱うためです。

『解。良い設計では、検索処理は結果をデータとして返し、表示は別の層に任せます』

例えば、検索結果を表す型を作れます。

```rust
#[derive(Debug)]
struct MatchLine {
    path: std::path::PathBuf,
    line_number: usize,
    line: String,
}
```

この形にすると、テストでは `println!` を見なくても検索結果を確認できます。

## 初出用語・関数の説明

- `std::path::Path`: 借用されたパスを表す型。ファイルやディレクトリの位置を扱う。
- `std::path::PathBuf`: 所有するパスを表す型。検索結果として保持したい場合に使う。
- `lines()`: 文字列を行ごとに分割するメソッド。
- `enumerate()`: イテレータの各要素に 0 から始まる番号を付けるメソッド。
- `contains`: 文字列が指定したパターンを含むか調べるメソッド。
- `display()`: パスを表示用の形に変換するメソッド。
- 再帰探索: ディレクトリの中にあるディレクトリを、さらに同じ手順で探索する方法。
- ANSI エスケープ: 端末上で色や表示効果を付けるための制御文字列。
- 部分失敗: 全体処理の一部だけが失敗すること。失敗した箇所を記録し、可能なら処理を継続する。
